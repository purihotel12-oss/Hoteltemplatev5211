# MASTER HOTEL WEBSITE TEMPLATE V5.2 — ENGINEERING CORRECTION PASS

V5.2 is an engineering correction pass over V5.1. It does not treat every external audit statement as true: only verified issues were changed.

## Corrected
- Proper Astro Tailwind integration dependency/configuration.
- Theme data is now actually connected to CSS variables.
- SEO site URL is centralized in `src/data/seo.ts` and consumed by hotel data.
- Disabled feature routes are removed from final `dist/` output and from the generated sitemap.
- Robots points to the final sitemap.
- Booking fallbacks no longer produce `#`.
- 404 navigation respects the Rooms feature flag.
- FAQ and breadcrumb JSON-LD are actually emitted where used.
- Required reusable hospitality components missing from V5.1 have been added.
- Gallery preview uses a stable responsive grid rather than a brittle 12-column auto-flow layout.

## Not changed
- `astro.config.mjs` was not treated as missing; it already existed.
- `scripts/postbuild.mjs` was not treated as missing; it already existed and was upgraded rather than duplicated.

## Validation
The source was checked after modification. A full `npm install`/`npm run build` could not be executed in this environment because npm registry access timed out / packages were not cached. The project should be validated locally with `npm install && npm run build`.


## V5.2.1 correction pass

- Fixed the remaining SEO source-of-truth disconnect: `src/data/hotel.ts` now consumes `src/data/seo.ts` instead of duplicating the site configuration.
- Removed duplicate theme token declarations from `global.css`; theme values are supplied by `BaseLayout.astro`.
- Added feature guards to optional pages so disabled modules redirect to the 404 route during normal page rendering, while the postbuild step removes disabled static artifacts from `dist/`.
- Made FAQ output conditional on actual FAQ data and feature state.
- Made the footer respect guest-information and FAQ feature flags.
- Added the blog detail feature guard.

Audit findings deliberately not repeated: `astro.config.mjs` and `scripts/postbuild.mjs` already existed in V5.2 and therefore were not recreated merely because an external audit incorrectly reported them as missing.

## V5.2.1 verified corrections
- `hotel.ts` now assigns the authoritative `seo` object directly; there is no duplicate SEO configuration.
- `seo.ts` carries the demo title previously applied as an ad-hoc override in `hotel.ts`.
- All previously added reusable hospitality components are now actually consumed by the pages/layouts where appropriate.
- `Header.astro` now uses valid raw JavaScript inside `<script is:inline>`.
- `BookingCTA` supports a light variant for dark-background CTA sections.
